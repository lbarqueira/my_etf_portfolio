# 📊 ETF Portfolio Report

Automated daily ETF portfolio report delivered to your inbox as a PDF, generated by a Jupyter notebook and scheduled via GitHub Actions — no server required.

---

## What it does

Every day at a scheduled time, GitHub Actions:

1. Runs `etf_portfolio_report.ipynb` with [papermill](https://papermill.readthedocs.io/), fetching live ETF prices via [yfinance](https://github.com/ranaroussi/yfinance)
2. Generates a single-page A4-landscape **PDF report** containing:
   - **Price Performance table** — current price vs reference price for the chosen period, with absolute and percentage delta coloured green/red
   - **Portfolio Holdings table** — shares, average purchase price, current value, and P&L (€ and %) per ETF, plus a totals row
   - **AI Analysis** — a structured commentary generated by Gemini 2.5 Flash covering executive summary, best/worst performer, overlap risk, and rebalancing recommendations
3. Emails the PDF to you via Gmail SMTP

## Period presets

The `PERIOD` parameter controls which reference price is used for the performance comparison:

| PERIOD | Reference price | Download window |
|--------|----------------|-----------------|
| `1D`   | Yesterday's close | 5 days |
| `5D`   | Close 5 trading days ago | 1 month |
| `1M`   | Close ~1 month ago | 3 months |
| `6M`   | Close ~6 months ago | 1 year |
| `YTD`  | First close of the year (Jan 1) | 1 year |
| `1Y`   | Close ~1 year ago | 2 years |
| `5Y`   | Close ~5 years ago | 10 years |
| `10Y`  | Close ~10 years ago | Max |

The GitHub Actions workflow is configured to run with `PERIOD=1M`. To change it, edit the `papermill` line in `.github/workflows/etf_report.yml`.

## GitHub Actions setup

The workflow runs on `ubuntu-latest` with Python 3.12. It is triggered:

- **On a schedule** — GitHub's native `schedule` cron runs daily at `11 21 * * *` (21:11 UTC = 22:11 Lisbon summer time)
- **Manually** — from the Actions tab using the "Run workflow" button

### Required secrets

Add these in your repo under **Settings → Secrets and variables → Actions**:

| Secret | Description |
|--------|-------------|
| `GMAIL_PASSWORD` | Gmail App Password (not your account password — generate one at [myaccount.google.com/apppasswords](https://myaccount.google.com/apppasswords)) |
| `GEMINI_API_KEY` | Gemini API key from [aistudio.google.com/apikey](https://aistudio.google.com/apikey) |

### Alternative: cron-job.org as external trigger (optional - not tested)

GitHub's built-in `schedule` cron can occasionally be delayed or skipped during periods of high load. If you ever experience reliability issues, [cron-job.org](https://cron-job.org) (free) can be used to trigger the workflow externally via the GitHub API `workflow_dispatch` event instead:

1. Create a free account at [cron-job.org](https://cron-job.org)
2. Create a new cronjob with these settings:
   - **URL**: `https://api.github.com/repos/YOUR_USERNAME/YOUR_REPO/actions/workflows/etf_report.yml/dispatches`
   - **Method**: `POST`
   - **Headers**: `Authorization: Bearer YOUR_GITHUB_PAT` and `Accept: application/vnd.github+json`
   - **Body**: `{"ref":"main"}`
3. Change the workflow trigger from `schedule` to `workflow_dispatch` only

Create a fine-grained GitHub PAT with **Actions: Read and write** permission on this repo.

## Timezone note

GitHub Actions cron uses **UTC**. The current schedule `11 21 * * *` fires at:

- **Summer (WEST, UTC+1)** — 22:11 Lisbon time
- **Winter (WET, UTC+0)** — 21:11 Lisbon time

Portugal clocks change twice a year (last Sunday of March and last Sunday of October), causing a one-hour seasonal drift. To keep a fixed local delivery time year-round, update the cron expression in `etf_report.yml` when the clocks change:

| Target (Lisbon) | Winter cron (UTC+0) | Summer cron (UTC+1) |
|-----------------|---------------------|---------------------|
| 21:11 | `11 21 * * *` | `11 20 * * *` |
| 13:00 | `0 13 * * *` | `0 12 * * *` |
